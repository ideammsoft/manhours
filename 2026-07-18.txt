1. 동명이인 구분 (이름 → 이름+전화번호)
----------------------------------------------------------------
[증상] 주간 근무표에 "이연재"가 2명인데, 신규 입력인데도 이전
       이연재의 값을 그대로 가져옴.

[원인] 이름만으로 키를 잡고 있었음.
       - 주간근무 테이블: 사업명+이름
       - 지급대장/근로자목록 조회: 이름
       - FileScreen 중복체크: 이름
       DB 확인 결과 실제로 이연재가 2명이었음.
         이연재 / 010-1234-0006 / 시급 없음
         이연재 / 010-1111-2222 / 시급 13,000

[수정]
  - AppConfig.cs : WorkerKey(name, phone) 추가 (전화번호는 숫자만 비교)
  - AppConfig.cs : WeeklyCols 에 "전화번호" 컬럼 추가
                   (EnsureTable 이 기존 DB에 자동 추가)
  - WeeklyScreen.cs : 로드/저장/적용 전부 이름+전화번호 키로 변경
                      그리드에 전화번호 열 추가 (눈으로 구분 가능)
  - WorkerScreen.cs : 지급대장 조회 키 변경
  - FileScreen.cs   : 중복체크를 이름+전화번호로 변경
                      → 두 번째 동명이인도 인원선택에 추가 가능해짐

[하위호환] 전화번호 없이 저장된 옛 주간근무 행은 이름으로 1회만
           물려받게 처리(동명이인이 공유하지 않도록).

2. 금액자동 체크해도 계산 안 됨  ★ 데이터 파괴 버그
----------------------------------------------------------------
[증상] 금액자동이 켜져 있는데 임금이 전부 0원.
       지우고 새로 추가해도 동일.

[원인] 금액자동은 정상 동작 중이었고, 시급이 0이라 전부 0이었음.
       시급이 사라지는 경로가 두 군데 있었음.

  (1) FileScreen.SaveToDb()
      인원선택 그리드는 시급을 표시하지 않는데, 화면에 보이는
      컬럼만 근로자목록에 저장 → 시급이 항상 빈 값으로 기록됨.

  (2) FileScreen.GetWorkerValues() + SaveWorkerUpdate()
      정보수정 시 화면에 없는 컬럼(시급/자격증/비고/상태)을
      빈 값으로 전체근로자에 UPDATE → 기존 데이터 파괴.
      이연재(0006)의 시급이 이렇게 지워진 것으로 추정.

[수정]
  - FileScreen.MergeHiddenCols() 신규 : 전체근로자 원본에서
    화면에 없는 컬럼을 채워 넣음
  - SaveWorkerUpdate : WHERE 이름 AND 전화번호 (동명이인 오염 방지)
  - WorkerScreen.LoadWorkers : 지급대장 시급이 비면
      근로자목록 → 전체근로자(원본) 순으로 폴백 (MasterWage)
  - WorkerScreen.UpdateWarnings : "시급이 없어 임금이 0원으로
    계산됩니다" 경고 줄 추가

[검증] 이연재 시급 13,000 자동 표시, 9-18 선택 시
       근무시간 8시간(휴게 1시간 공제) → 기본급 104,000원.

5. 휴게자동이란? (질문 답변)
----------------------------------------------------------------
법정 휴게시간 자동 공제 기능.
  - 하루 4시간 이상 근무 → 30분 공제
  - 하루 8시간 이상 근무 → 60분 공제
  (설정 → 법정기준(연도별) 에서 조정 가능)
예) 9-18 은 9시간이지만 체크 시 8시간으로 집계됨.
    해제하면 9시간 전부가 근로시간.

6. 주간 근무표 진입 시 전화번호 자동 기록
----------------------------------------------------------------
[요청] 메뉴 누를 때 주간표 저장을 자동으로 하면 되지 않나?

[판단] 그대로 하면 위험. 주간표 저장은 DELETE 후 전체 재작성인데
       로스터에 휴직/퇴사자가 빠져 있어 그분들 패턴이 삭제됨.

[대안] 전화번호가 비어 있는 옛 행에 UPDATE 로 전화번호만 채우는
       마이그레이션만 수행. 시간 데이터는 건드리지 않음.
       (WeeklyScreen.MigrateWeeklyPhones)

[검증] 저장 버튼 없이 메뉴 진입만으로 6명 전원 전화번호 기록,
       근무시간은 그대로.

8. 주간표 적용 규칙 정리
----------------------------------------------------------------
(1) 7월 전체 / 선택 주 적용 시 주간표 자동 저장
    - 확인을 누르면 적용 직전에 저장. 실패 시 적용 중단.
    - 저장 자체도 안전하게 변경 : 전체 DELETE 대신 화면에 있는
      사람의 행만 교체 → 휴직/퇴사자 패턴 보존
      (WeeklyScreen.SaveRows)

(2) 주간표에 시간이 없는 사람
    - 적용 대상을 "현재근무 전원"으로 넓히고, 시간이 없으면
      해당 날짜를 비움
    - 단, 이미 지급대장에 있는 사람만 손댐
      (시간이 비었다고 새 인원을 끌어들이지 않음)
    - 적용 결과 그 달 근무시간이 하나도 남지 않으면
      근로자목록·지급대장에서 제거
      → 다른 주에 직접 입력한 근무가 있으면 유지되므로
        수동 입력 데이터는 보호됨

(3) 인원선택에서 제외하면 지급대장에서도 삭제
    - FileScreen.PurgePayroll() 추가
    - 근무시간 데이터가 있어도 제외하면 사라짐

(4) 인원선택 화면 이탈 시 자동저장  ★ 핵심
    - 기존에는 "저장 다음 단계" 버튼을 눌러야만 반영되어,
      사이드바로 이동하면 제외가 통째로 날아감
      → "제거 방법이 없다"의 진짜 원인
    - MainForm.ShowScreen 에 FileScreen.SaveRoster() 추가
      (근무시간 입력/장비변경에는 이미 있던 패턴)
    - 안전장치 : 목록이 0명이면 저장하지 않음
      (화면만 열어도 그 달 인원이 통째로 날아가는 사고 방지)

(5) 적용 시 마스터 시급이 비어 있으면 지급대장 시급을 덮어쓰지 않음

9. 임금명세서 천단위 콤마
----------------------------------------------------------------
[원인] Won() 이 "1,638,000" 으로 만들어 주는데, ApplyTokens 가
       "숫자만 남으면 숫자로 넣는다" 하면서 콤마를 떼고 저장.
       셀 서식이 General 이라 1638000 으로 표시됨.
       계산방법란은 문장 속이라 텍스트로 남아 콤마가 살아 있었음.

[수정] PrintScreen.ApplyTokens
         cell.Value = n;
         if (text.Contains(',')) cell.Style.NumberFormat.Format = "#,##0";
       콤마 유무로 금액만 골라냄. 년도(2026)/사번/근무일수 같은
       값은 콤마가 없어 서식이 안 붙음 (2,026 방지).

[검증] 실제 7월 명세서 출력 후 Excel 로 표시 문자열 확인
         기본급   294000 → '294,000'
         국민연금  13230 → '13,230'
         공제액계  27647 → '27,647'
         실지급액 266353 → '266,353'
       xlsx 내부 numFmtId=164 (#,##0). PDF 는 Excel COM 으로
       출력하므로 동일하게 반영됨.
       ※ 근로계약서(ApplyTokens 공용)에도 함께 적용됨.

 개발 환경 이슈 — Smart App Control
================================================================
빌드한 manHours.dll 이 Windows Smart App Control 에 차단되어
앱이 창도 못 띄우고 즉시 종료됨.

  System.IO.FileLoadException:
  애플리케이션 제어 정책에서 이 파일을 차단했습니다. (0x800711C7)

  확인 : HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy
         VerifiedAndReputablePolicyState = 1  (켜짐)

[해결] 빌드 후 서명하면 정상 실행됨.

  signtool sign /a /s my /n "mmsoft" /fd sha256 ^
    /tr http://timestamp.digicert.com /td sha256 ^
    bin\Debug\net8.0-windows\manHours.dll ^
    bin\Debug\net8.0-windows\manHours.exe

  signtool 경로:
  C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe

※ Smart App Control 끄기는 비권장 — 한 번 끄면 Windows 를
  재설치해야 다시 켤 수 있음.
※ sign.bat 은 버전 증가 + GitHub 자동 커밋/푸시 + FTP 업로드까지
  하므로 검증 목적으로는 실행하지 말 것. 서명 명령만 떼어 쓸 것.
※ 매 빌드마다 반복되므로 .csproj PostBuild 자동화 검토 필요.
